# 中枢震荡选股

将「日线最近中枢的价格宽度较大、收盘仍处于区间内」转成可复核的观察名单。默认只筛选并报告；用户要求加入或更新分组时操作「中枢震荡」。这是独立观察组，不是第四类买点，也不自动更新「一买」「二买」「三买」组。

## 默认口径

用户的明确条件优先；未指定时沿用下表，不重复询问默认项。

| 项目 | 口径 |
| --- | --- |
| 股票池 | 沪深主板。结合证券主表与代码识别；排除已证实 ST、退市整理、停牌标的。仅有名称标记时披露资格核验边界，不假装拥有完整状态表 |
| 行情截止 | 北京时间最近完整交易日的已发布收盘。盘中不把当天尾行当作完整日线；历史研究按指定截止裁剪 |
| 输入 | 前复权日线，目标最近1000根；逐股报告实际条数、起止和数据来源，短样本不伪装成满样本 |
| 结构 | 项目当前 chan.py 的日线输入笔中枢 `centers`。线段中枢 `segment_centers` 另列，不能混入同一排序 |
| 最后一个 | 在当前连续有效输入段中按中枢 `(end, start)` 取最新。先取最后一个，再筛宽度与近期性；不能倒找历史上更宽的中枢替代 |
| 近期 | 最后中枢的构成末端落在最近20个实际交易日内；中枢起点可以更早。不是20个自然日，也不是股价近期碰过旧区间 |
| 宽度 | `width_pct = (high - low) / low × 100`，门槛 `>= 10%`；使用中枢上下沿，不使用围绕中枢的最高/最低价 |
| 震荡观察 | `low <= close <= high`。区间上方、区间下方分别列出；触及边界保留精确值，不因四舍五入改变分类 |
| 位置 | `position_pct = (close - low) / (high - low) × 100`，0%为下沿，100%为上沿；贴近下沿不等于止跌 |
| 排序与数量 | 按宽度降序，等宽按完整代码排序。保留全部结果；聊天可展示前10只并明确展示范围，完整报告/CSV不截断 |
| 确认状态 | 保留算法原始 `confirmed`。未确认但数据可用的宽中枢可列「演化中候选」；数据不足、结构缺失另列 `unknown` |

宽度是几何价差，不是预期收益；股价暂处区间内也不能保证下一次仍回到上沿。算法已确认和原文严格递归确认不是同一层证据。只要求宽中枢筛选时无需额外完成30分钟买点判定；用户问能否介入、严格中枢或买点时，另行核对相应级别和次级别完成证据。

## 取数与结构计算

1. **先核对环境和发布状态。** 读取 [项目 API 契约](../chan-stock-screen/references/project-api.md) 的数据入口部分，探测实际服务地址；查看 `/api/data/status`、`/api/pipeline/jobs` 和 `/api/settings/capability-matrix`。状态页的全局最新日期不证明每只股票都更新；记录要求截止、实际截止、数据源与复权口径。发布中或批次不一致时等待稳定快照，无法取得则报告未完成。
2. **理解原文与实际引擎。** 按 [原文索引](../chan-stock-screen/references/pdf-source.md) 读取第20课的中枢边界及延续定义，需要辨别笔、线段和递归级别时补读第17、63、64课。检查 [引擎契约](../../../docs/chan-engine.md) 和实际图表响应的 `engine/version/profile_id/algorithm_config`。运行服务与本地算法不同则分别报告，不能混标或擅自升级引擎。
3. **批量读取。** 通过 [KlineRepository](../../../backend/app/tickflow/repository.py) 的 `get_instruments()`、`get_daily_batch()` 获取窄列数据；不要对全市场逐股请求完整图表，也不要绕过仓库散读行情 Parquet。先按实际交易日确定足够长的读取范围，再逐股排序取最后1000根；不足时保留真实覆盖，不静默改变用户指定截止或股票池。调用前后用 `get_matrix_data_generation("stock", readonly=True)` 检查一致，计算/入组前再次核对。缓存返回结果仍须按截止裁剪。
4. **逐股检查质量。** 检查最新日、重复日期、有限正数 OHLC、`low <= min(open, close) <= max(open, close) <= high`，以及成交量/金额和相关交易日缺口。解释停牌等已知缺口；无法解释的相关缺口进入待核验，不补零或跨坏行拼结构。当前连续有效段必须足以构造中枢。主表资格、数据可用性、算法结构状态分别记录；未发现结构不代表不存在原文定义的中枢。
5. **复用现有计算。** 使用 [ChanReplay](../../../backend/app/indicators/chan_runtime.py) 和 [图表结构适配器](../../../backend/app/indicators/czsc_chart.py)，保持项目参数和输入单位。记录笔数、构成起止、`confirmed` 与未完成末端；关闭单笔中枢的现有约束不可为凑结果放宽。若引擎合并了中枢，另记合并数量，说明采用算法合并区间，不冒充初始三段的共同重叠区间。对 `low <= 0` 或 `high <= low` 不计算有效宽度/位置。
6. **先定最后中枢，再应用条件。** 分出区间内、上方、下方及待核验清单；报告名称排除、实际计算、数据不足、无可计算中枢和宽度命中数量。区间内可按位置说明靠近哪一侧，但不把较低位置写成更高胜率。
7. **验证展示名单。** 对聊天展示项及拟新增成员，使用实际图表 API 核对最新中枢、截止、条数、价格、算法和数据版本；批量规模大时分批并控制并发。与同截止市场快照比较收盘，只能证明应用内部一致，不能写成独立交易所逐根核验。历史截止不能用无历史参数的当前图表 API作证明，应通过仓库同截止输入和现有适配器复算。

必要时将本次输入清单、参数、数据版本、逐股状态、完整 CSV、图表核对结果保存到运行时数据目录下新的独立研究目录，不覆盖旧研究或行情文件，不提交用户数据。不要把本次日期、股票名单、分组 ID、主机端口和机器绝对路径写死为后续运行的默认值。

## 分组操作

只在用户要求加入或更新分组时执行；已经明确授权的本次操作无需再次确认。用户指向上一条表格的「这些」时，以该表实际展示的股票为范围，不擅自扩大到完整筛选结果。历史研究默认不覆盖当前分组；用户明确要求保存历史清单时，记录其截止日期。

「中枢震荡」承载研究观察项，允许明确披露的算法未确认候选；资格/数据缺口必须在报告中可见，不以入组证明买点成立。若用户明确要求保存指定候选名单，可按其指定范围保存；自动从新筛选结果新增时，未解决的数据质量或资格问题先留待核验。

写入前读 [项目分组接口与保护语义](../chan-stock-screen/references/project-api.md)，只复用其中多对多成员操作契约；本技能的目标组和候选门槛以上文为准，不继承三类买点组的入组流程或「不新建震荡组」约定。

- 按名称读取 `GET /api/watchlist/groups`；「中枢震荡」缺失则 `POST /api/watchlist/groups`，请求 `{"name":"中枢震荡"}`，随后回读获取 ID。同名冲突停止有歧义的写入。
- 读取 `GET /api/watchlist` 并保存操作前快照。已在自选的股票用 `POST /api/watchlist/groups/{group_id}/members/{symbol}`；尚未在自选的股票用 `POST /api/watchlist`，请求包含 `symbol`、`group_id`。新股可附带日期、候选区间和未确认状态的简短备注；不覆盖已有备注、加入时间或其他分组。
- 默认「加入/更新」采用追加并报告原成员当前状态。只有用户要求清理/移除，且本轮有同口径明确不再符合的证据时，才用 `DELETE /api/watchlist/groups/{group_id}/members/{symbol}` 移除此组成员关系。用户指定名单移除时按其范围执行。数据缺失、未扫描、展示截断或本次池外都不能作为筛选清理依据。
- 写前再次核对自选和分组；并发变化先重读并重新计算尚未执行的差集，不覆盖他人修改。超时先回读核实是否成功，确认未生效才最多补试一次；无法核实或持续失败则停下并报告已完成、失败和未执行项。
- 写后回读比较预期成员，并核对原有其他分组、备注、加入时间及非目标成员保留。只有核对一致才报告完成；不清空重建、不删除股票、不使用互斥 `PUT /api/watchlist/{symbol}/group`。

## 报告

先给截止日、股票池、实际覆盖、价格口径和完整/部分完成状态。区间内观察表至少包括代码名称、最后中枢构成起止、上下沿、宽度、收盘、位置、笔数、算法确认状态；另列上方、下方和待核验项，附完整清单位置。

区分「满足本次宽度/位置条件」「算法确认」「严格递归级别已证实」。未做次级别复核时直接说明没有买点确认。构成端点日期不等于首次识别日期；未回放识别时间则填未知。

有分组操作时列出实际新增、保留、移除、待核验和回读状态；只读筛选说明未写分组。不给订单、通知、定时任务或收益承诺。

本技能复用现有项目能力，不为一次筛选修改核心服务、引擎参数或数据源。需要开发或调试代码时，先遵循 [CONTRIBUTING.md](../../../CONTRIBUTING.md) 和 [二次开发指南](../../../docs/secondary-development.md)。
