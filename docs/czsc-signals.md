# CZSC 日线辅助信号

CZSC 信号可作为普通日线策略的买卖触发器，并进入现有策略回测。首版支持 A 股股票，采用 CZSC 1.0.1 原生算法。所有名称均表示算法辅助判定，不能当作严格缠论买卖点已经确认。

## 安装与使用

在后端目录安装可选依赖，然后重新启动后端：

```bash
uv sync --frozen --extra czsc
```

使用仓库的 `dev.sh` 或 Docker 构建时，沿用已有的 `BACKEND_EXTRAS` 配置并追加 `czsc`；多个 extra 用空格分隔。例如开发启动可使用 `BACKEND_EXTRAS="czsc dev" ./dev.sh`。这会在依赖同步时保留 CZSC。

开发环境验证时同时保留开发依赖：

```bash
uv sync --frozen --extra czsc --extra dev
uv run --frozen --extra czsc --extra dev pytest tests/test_czsc_signals.py tests/test_czsc_monitor.py -q
```

在信号页查看说明，在策略设置或回测设置中选择 CZSC 辅助信号。未安装、版本不匹配、ETF、分钟策略及当前不接收这些触发器的策略类型会显示不可用原因。已保存的选择仍可移除。

引用 CZSC 入场信号时，入场成交使用次交易日开盘；引用 CZSC 出场信号时，出场成交使用次交易日开盘。不同信号按现有 OR 规则组合；各信号先独立计算首次成立触发，再组合。成交仍受原有 T+1、停牌、涨跌停、费用、滑点与资金约束影响，触发并不保证成交。

### 直接选择回测策略

信号本身是策略中的买卖触发器，不会自动成为策略列表条目。仓库提供三份可通过“新建自定义策略”的代码编辑器保存的配对模板：

- [CZSC 一买/一卖辅助](./examples/czsc-strategies/custom_czsc_first_bs.py)
- [CZSC 均线二买/二卖辅助](./examples/czsc-strategies/custom_czsc_second_bs.py)
- [CZSC 均线三买/三卖辅助](./examples/czsc-strategies/custom_czsc_third_bs.py)

保存后，在“回测 → 策略回测 → 自定义”选择模板，建仓和清仓均设为“次交易日开盘”；页面也提供一键修正成交口径的按钮。模板关闭额外基础过滤、评分、止损及持有天数退出，用于验证原生信号配对，可以在策略设置中自行增加条件。选股的候选池与买卖触发是分开的：模板以全部股票为候选池，入场仍需相应信号首次成立。

这些模板通过现有自定义策略 API 保存到持久化数据目录并热加载，属于 L1 扩展。仅安装 CZSC 组件不会自动安装模板。

## 首批算法与固定参数

| 信号 ID | 显示含义 | CZSC 原生算法 | 参数 |
| --- | --- | --- | --- |
| `signal_czsc_first_buy` | 一买辅助 | `cxt_first_buy_V221126` | `di=1` |
| `signal_czsc_first_sell` | 一卖辅助 | `cxt_first_sell_V221126` | `di=1` |
| `signal_czsc_second_buy` | 均线二买辅助 | `cxt_second_bs_V230320`，匹配二买 | `di=1, SMA21` |
| `signal_czsc_second_sell` | 均线二卖辅助 | `cxt_second_bs_V230320`，匹配二卖 | `di=1, SMA21` |
| `signal_czsc_third_buy` | 均线三买辅助 | `cxt_third_bs_V230318`，匹配三买 | `di=1, SMA34` |
| `signal_czsc_third_sell` | 均线三卖辅助 | `cxt_third_bs_V230318`，匹配三卖 | `di=1, SMA34` |

结构参数固定为 `min_bi_len=6, max_bi_num=50`，不读取进程环境变量覆盖。首版不提供参数优化界面。算法依据为 [CZSC 原生结构信号源码](https://github.com/waditu/czsc/blob/v1.0.1/crates/czsc-signals/src/cxt.rs)；未来升级必须重新验证参数、返回值与时间语义。

## 时间与可计算性

- 输入为标准化 enriched 前复权日线，成交量从手显式乘 100 转成 RawBar 的股，成交额保持元。不直接调用供应商行情接口。
- 每个标的按交易日期升序逐根更新。北京时间当日 15:00 前的日线及未来日期不参与识别；同一标的同日重复输入会报错。
- 信号写在当时首次识别到它的日线上，绝不回填到更早的分型或笔端点。追加未来 K 线不得改变同一输入前缀的输出；价格复权修订属于输入变化，需重新计算。
- 一个信号从有效的 `False` 变为 `True` 才触发。连续成立不重复触发；首次具备计算条件时只建立基线。回测预热阶段的状态延续到正式区间。
- 预热读取目标为 500 根日线；日历窗口只用于放宽数据读取，实际就绪取决于标的拥有的有效 K 线、笔及相关均线输入。一买卖至少需要 5 笔，二、三买卖至少需要 7 笔及其均线所需历史。
- 缺失、非有限或非法 OHLC/量额中断当前标的的分析状态，重新积累结构。没有数据的交易日不能靠补零或填充价格虚构结构；本功能不会自动下载缺失数据。

回测结果的 `stats.czsc_coverage` 和策略结果的 `czsc_coverage` 展示每个信号的可计算行数、不可计算行数、涉及标的数及原因：

| 原因 | 含义 |
| --- | --- |
| `insufficient_structure` | 笔数或相应均线输入尚不足 |
| `missing_data` | 日线数据缺失或无效 |
| `unclosed_bar` | 当日日线尚未收盘或日期在未来 |
| `baseline` | 首次可计算，仅建立状态基线 |

原生函数的“其他”可能来自样本不足，也可能表示没有命中。适配层先检查结构和均线输入；不可计算输出保留为空值及原因，成交掩码跳过这些行。零触发的失败结果同样保留覆盖情况。

## 接入与兼容边界

二次开发起点为 `414646f02d0d41bfa9f082bafaca4a437a44faca`。

本次接入属于 L3 的局部源码扩展：新增 `app/indicators/czsc_signals.py`，接入既有信号依赖解析、按需计算、策略结果与回测输出。`compute_signals(needed=None)` 仍仅计算既有默认信号，动态策略的全量依赖兜底也不会自动启用 CZSC。默认安装及普通指标刷新不加载原生运行库。

策略代码直接读取 CZSC 列时，需在 `REQUIRED_FEATURES` 声明完整的 `signal_czsc_*` 列名；这类依赖同样参与预热、可用性和盘中监控检查，并要求入场使用次交易日开盘。策略详情返回 `required_features` 供界面识别这些依赖。

CZSC 结果不写入 enriched Parquet，不引入新数据源或第二套撮合引擎。历史基础数据继续使用现有仓库与缓存，结构信号按本次选择回放。结构预热需求进入回测依赖计划；选股历史读取遵循声明的长窗口，避免被旧的 180 自然日上限截断。

修改或重置涉及 CZSC 的策略配置时，只失效对应策略的结果、当日命中历史和实时监控状态。其他策略缓存保留。前端沿用集中查询键和共享查询，刷新配置后重新获取策略结果。

首版盘中监控拒绝含这些信号的策略。历史规则或后来被改成 CZSC 的策略会暂停评估并显示原因，避免用盘中快照假充已收盘日线。自选提醒和多周期共振不在这一版范围内；图表展示见 [CZSC 日线结构图](./czsc-chart.md)，辅助事件仍沿用本节的识别日口径。

安装与原生算法测试覆盖当前 Linux/Python 环境；其他平台未据此视为已经完成运行验证。锁文件原镜像在本次解析时返回 403，因此重新使用 PyPI 解析；既有第三方包版本保留，仅加入 CZSC 的依赖及已有项目版本元数据更新。

## 验证范围

固定随机样本逐根调用原生算法核对全部六个信号，并比较 600 根输入前缀与追加至 900 根后的同一前缀。测试同时覆盖初始基线、持续成立、跨标的隔离、非法数据、未收盘日线、依赖缺失/版本不符/加载失败、次交易日成交、失败结果的 SSE 覆盖统计，以及策略配置修改后的定向缓存失效。

2026-09-14 在当前 Linux/Python 3.13 环境进行的小规模耗时检查：原生库预加载后，20 个合成标的各 550 根日线（共 11,000 行），计算六个信号用时 6.303 秒。此检查只说明该输入规模下的计算耗时，不代表全市场吞吐或真实策略收益；首版未完成全市场性能验证。
